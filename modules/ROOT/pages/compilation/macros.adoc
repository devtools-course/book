== `#define`

Макрос это правило замены. Бывает двух видов.

*Объектоподобный* макрос, просто имя:

[,cpp]
----
#define PI 3.14159
#define DEBUG_MODE
#define MAX_SIZE (1024 * 1024)
----

*Функциоподобный* макрос, имя со скобками:

[,cpp]
----
#define SQUARE(x) ((x) * (x))
#define MAX(a, b) ((a) > (b) ? (a) : (b))
----

Обратите внимание на скобки вокруг каждого аргумента и вокруг всего тела. Хоть это и выглядит странно, но так надо. Классический пример:

[,cpp]
----
#define BAD_SQUARE(x) x * x

int y = BAD_SQUARE(2 + 3);   // разворачивается в 2 + 3 * 2 + 3, то есть 11, а не 25
----

Второй классический капкан - вычисление аргумента несколько раз:

[,cpp]
----
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int i = 0;
int m = MAX(i++, 5);   // i++ подставится дважды, i увеличится дважды
----

Именно поэтому в C++ макросы почти всегда надо заменять на `constexpr`-переменные и `inline`-функции: они подчиняются правилам языка, а не правилам текстовой замены.

[,cpp]
----
constexpr double kPi = 3.14159;                       // вместо #define PI
constexpr int Square(int x) { return x * x; }         // вместо #define SQUARE
----

Многострочный макрос пишется через обратный слеш в конце строки (та самая фаза 2):

[,cpp]
----
#define LOG(msg)                       \
    do {                               \
        std::cerr << __FILE__ << ":"   \
                  << __LINE__ << " "   \
                  << (msg) << "\n";    \
    } while (0)
----

Обёртка `do { ... } while (0)` нужна, чтобы макрос вёл себя как одна инструкция и корректно работал внутри `if` без фигурных скобок. После слеша не должно быть *ни одного* пробела, иначе склейки не произойдёт и вы получите загадочную ошибку.

Отменить макрос можно через `#undef`:

[,cpp]
----
#undef MAX_SIZE
----

Задать макрос снаружи, из командной строки, можно флагом `-D`:

[,console]
----
$ g++ -DDEBUG_MODE -DMAX_SIZE=2048 main.cpp
----

Это ровно то же самое, как если бы в начале файла было написано `#define DEBUG_MODE` и `#define MAX_SIZE 2048`. Отсюда весь механизм конфигурации сборки: один и тот же исходник собирается по-разному в зависимости от `-D`.

Есть ещё предопределённые макросы, которые компилятор задаёт сам: `+__FILE__+`, `+__LINE__+`, `+__DATE__+`, `+__func__+`, `+__cplusplus+` (номер стандарта), `+__GNUC__+` (собираемся gcc), `+_WIN32+`, `+__linux__+`. Полный список того, что задано у вас:

[,console]
----
$ g++ -dM -E -x c++ /dev/null | sort | head
----

== `#ifdef`, `#ifndef`, `#if`

Условная компиляция: кусок текста либо попадает в единицу трансляции, либо не попадает вообще. Не «не выполняется в рантайме», а физически отсутствует к моменту компиляции.

[,cpp]
----
#ifdef DEBUG_MODE
    std::cerr << "debug build\n";
#endif

#ifndef NDEBUG
    check_invariants();
#endif

#if __cplusplus >= 202002L
    // код на C++20
#elif __cplusplus >= 201703L
    // код на C++17
#else
    #error "Нужен как минимум C++17"
#endif
----

Проверить, что реально остаётся после вырезания веток, можно всё тем же `-E`:

[,console]
----
$ g++ -E -DDEBUG_MODE main.cpp | grep -A2 "debug build"
----

WARNING: Внутри вырезанной ветки код *не проверяется компилятором вообще*. Там может лежать любая синтаксическая чушь, и сборка пройдёт. Это главная причина, почему код под редким `#ifdef` (скажем, под `+_WIN32+`, который вы никогда не собираете) незаметно гниёт.

Отдельно про `NDEBUG`: этот макрос отключает `assert`. Он не задаётся компилятором сам, его принято передавать в релизных сборках. Если собираете руками, `assert` останется включённым, пока вы явно не напишете `-DNDEBUG`.
