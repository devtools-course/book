== `static` и внутреннее связывание

Ключевое слово `static` в C++ перегружено значениями, и на этапе сборки нас интересует одно: *внутреннее связывание* (internal linkage).

[,cpp]
----
static int counter = 0;              // глобальная, но видна только в этой TU
static void helper() { ... }         // функция, видна только в этой TU
----

Такой символ виден только внутри своей единицы трансляции. В `nm` он будет строчной буквой:

[,console]
----
$ nm util.o
0000000000000000 t _ZL6helperv     <1>
0000000000000010 T _Z6publicv      <2>
----
<1> Строчная `t`, функция локальная.
<2> Заглавная `T`, функция доступна другим объектникам.

Зачем: две разные TU могут завести по своей `static void helper()`, и конфликта не будет. Без `static` линковщик увидит два одинаковых символа и скажет `multiple definition`.

В современном C++ для того же самого предпочитают безымянные пространства имён, они работают и для типов:

[,cpp]
----
namespace {
    int counter = 0;
    void helper() { ... }
}
----

== `inline` и правило одного определения

Ещё одно слово, которое почти все понимают неправильно. `inline` **не** приказывает компилятору встроить функцию в место вызова. Компилятор решает это сам, исходя из размера и уровня оптимизации, и делает это с функциями без `inline` тоже.

Что `inline` делает на самом деле: разрешает *повторять определение функции в разных единицах трансляции*.

Зачем это нужно. Есть *правило одного определения* (One Definition Rule, ODR): у каждой сущности в программе должно быть ровно одно определение. Если положить в заголовок

[,cpp]
----
// util.h
int square(int x) { return x * x; }    // определение!
----

и включить его в два `.cpp`, то в двух объектниках окажется по символу `_Z6squarei` с классом `T`, и линковщик честно скажет:

[,text]
----
/usr/bin/ld: b.o: multiple definition of 'square(int)'; a.o: first defined here
----

Добавляем `inline`:

[,cpp]
----
inline int square(int x) { return x * x; }
----

и линковщик, увидев несколько определений, молча оставляет одно. В `nm` символ станет слабым:

[,console]
----
$ nm -C a.o | grep square
0000000000000000 W square(int)      <1>
----
<1> `W` - weak. Дубликаты таких символов не считаются ошибкой.

Отсюда практические следствия:

* Функции, определённые *внутри* класса, неявно `inline`. Поэтому заголовки с классами включаются куда угодно и не ломают линковку.
* Шаблоны тоже ведут себя так: их определения обязаны быть видны в каждой TU, и дубликаты инстанцирований схлопываются.
* С C++17 есть `inline`-переменные, что наконец позволило держать глобальную константу прямо в заголовке:
+
[,cpp]
----
inline constexpr double kPi = 3.14159;
----

WARNING: Если дать `inline`-функции *разные* определения в разных TU, ошибки не будет, а поведение будет неопределённым: линковщик выберет любое из них. Это классический источник загадочных багов, когда один `.cpp` собран с одним `-D`, а другой с другим.

== Слабые символы и видимость

Раз уж зашла речь про `W`, стоит знать про слабые символы явно.

[,cpp]
----
__attribute__((weak)) void on_event() { /* заглушка */ }
----

Слабый символ - это определение с пониженным приоритетом. Если где-то в программе найдётся *сильное* определение того же символа, линковщик возьмёт его, а слабое проигнорирует, и никакой ошибки не будет. Так делают точки расширения: библиотека кладёт слабую заглушку, а пользователь при желании подменяет её своей реализацией.

Второй механизм - *видимость символов* (visibility). По умолчанию в разделяемой библиотеке наружу торчат вообще все глобальные символы. Это плохо: раздувается таблица динамических символов, замедляется загрузка, а внутренние детали становятся частью публичного интерфейса.

[,console]
----
$ g++ -fvisibility=hidden -shared -fPIC lib.cpp -o libfoo.so
----

Теперь по умолчанию наружу не торчит ничего, и то, что должно быть публичным, помечается явно:

[,cpp]
----
#define EXPORT __attribute__((visibility("default")))

EXPORT void public_api();          // видна снаружи
void internal_helper();            // не видна
----

Проверить, что получилось, - `nm -D` (динамические символы):

[,console]
----
$ nm -D --defined-only libfoo.so | c++filt
----
