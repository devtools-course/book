== Name mangling

Вот это `_Z3addii` вместо `add` и есть *name mangling*, коверканье имён.

Причина: линковщик работает с плоской таблицей строк-символов и ничего не знает про C++. А в C++ можно написать три функции с одним именем:

[,cpp]
----
int  max(int, int);
double max(double, double);
namespace geo { int max(int, int); }
----

Если бы все три попали в объектный файл как `max`, линковщик не смог бы их различить. Поэтому компилятор кодирует в имя символа всё, что нужно для однозначности: пространство имён, имя класса, типы аргументов, квалификаторы `const` и `volatile`, ссылочность.

Расшифруем `_Z3addii`:

* `_Z` - префикс искажённого имени (Itanium C++ ABI, его используют gcc и clang на всех Unix-платформах).
* `3add` - имя длиной 3 символа, `add`.
* `i` `i` - два параметра типа `int`.

Тип возвращаемого значения в схему обычно *не входит*. Именно поэтому в C++ нельзя перегрузить функцию только по возвращаемому типу: получились бы два одинаковых символа.

Читать это руками необязательно, для расшифровки есть утилита `c++filt`:

[,console]
----
$ c++filt _Z3addii
add(int, int)

$ c++filt _ZNSt6vectorIiSaIiEE9push_backERKi
std::vector<int, std::allocator<int> >::push_back(int const&)
----

Она умеет работать и как фильтр, разбирая целый поток:

[,console]
----
$ nm main.o | c++filt
$ g++ main.cpp 2>&1 | c++filt      <1>
----
<1> Очень помогает, когда линковщик ругается искажёнными именами.

Посмотреть таблицу символов объектного файла - утилита `nm`:

[,console]
----
$ nm main.o
0000000000000000 T _Z3addii
                 U _Z5printPKc
0000000000000016 T main

$ nm -C main.o                     <1>
0000000000000000 T add(int, int)
                 U print(char const*)
0000000000000016 T main
----
<1> Флаг `-C` это встроенный `c++filt`, можно не городить пайп.

Буква во второй колонке это класс символа, и её обязательно надо уметь читать:

[cols="1,4"]
|===
|Буква |Что значит

|`T`
|Определён в секции кода, виден снаружи (global text). Такой символ могут использовать другие объектники.

|`t`
|Определён в секции кода, но локальный. Так выглядит `static`-функция.

|`U`
|Undefined. Символ используется, но не определён здесь. Его должен предоставить кто-то другой на линковке.

|`D`
|Инициализированная глобальная переменная.

|`B`
|Неинициализированная глобальная переменная (секция `.bss`).

|`W`
|Weak symbol, слабый символ.

|`R`
|Константа, только для чтения.
|===

Практически весь навык отладки линковки сводится к тому, чтобы найти символ с `U` в одном файле и убедиться, что где-то есть тот же символ с `T`.

== `extern "C"`

Иногда искажение имён надо выключить: например, чтобы C++ код мог вызвать функцию из библиотеки на C, или чтобы вашу функцию мог вызвать кто-то извне по предсказуемому имени.

[,cpp]
----
extern "C" void my_api_function(int x);

extern "C" {
    void first(void);
    void second(void);
}
----

Внутри `extern "C"` имя попадает в объектник как есть, без `_Z` и кодирования типов. Из этого прямо следует, что такую функцию *нельзя перегружать*: два варианта дали бы один и тот же символ.

Стандартный приём для заголовка, который должен работать и из C, и из C++:

[,cpp]
----
#ifdef __cplusplus
extern "C" {
#endif

void my_api_function(int x);

#ifdef __cplusplus
}
#endif
----

Макрос `+__cplusplus+` определён только в C++, так что компилятор C просто не увидит незнакомых ему слов.
