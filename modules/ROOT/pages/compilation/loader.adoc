== `ldd`: от кого зависит бинарь

[,console]
----
$ ldd ./app
        linux-vdso.so.1 (0x00007ffd8b1f2000)
        libstdc++.so.6 => /lib/x86_64-linux-gnu/libstdc++.so.6 (0x00007f3c4a000000)
        libm.so.6 => /lib/x86_64-linux-gnu/libm.so.6 (0x00007f3c49f00000)
        libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007f3c49d00000)
        /lib64/ld-linux-x86-64.so.2 (0x00007f3c4a200000)
----

Слева нужное имя, справа найденный файл. Если библиотека не нашлась, вместо пути будет `=> not found`, и это ровно та причина, по которой программа падает при запуске с `error while loading shared libraries`.

WARNING: `ldd` на непроверенном бинаре запускать не стоит. В некоторых реализациях он работает через запуск программы со специальными переменными окружения, так что вредоносный файл может получить исполнение. Безопасная альтернатива - `objdump -p ./app | grep NEEDED` или `readelf -d ./app`.

== Где загрузчик ищет библиотеки

Порядок поиска примерно такой:

. `DT_RPATH`, зашитый в бинарь (устаревший, но всё ещё встречается).
. Переменная окружения `LD_LIBRARY_PATH`.
. `DT_RUNPATH`, зашитый в бинарь.
. Кэш `/etc/ld.so.cache`.
. Системные каталоги: `/lib`, `/usr/lib` и производные.

`LD_LIBRARY_PATH`::
Список каталогов через двоеточие, где искать до системных путей.
+
[,console]
----
$ LD_LIBRARY_PATH=/opt/mylib/lib ./app      <1>
$ export LD_LIBRARY_PATH=/opt/mylib/lib     <2>
----
<1> Только для одного запуска, так и надо делать.
<2> На всю сессию. Так лучше не делать: переменная унаследуется всеми процессами и может подсунуть чужую библиотеку совсем другой программе.

`ldconfig`::
Утилита, которая пересобирает кэш `/etc/ld.so.cache` по каталогам из `/etc/ld.so.conf` и `/etc/ld.so.conf.d/`. Именно её надо позвать после того, как положили новую библиотеку в системный каталог.
+
[,console]
----
$ sudo cp libfoo.so.1.0.0 /usr/local/lib/
$ sudo ldconfig                             <1>
$ ldconfig -p | grep foo                    <2>
----
<1> Пересобрать кэш и заодно создать симлинки по soname.
<2> Показать, что сейчас в кэше.

`-rpath`::
Зашить путь поиска прямо в бинарь на этапе линковки. Работает без переменных окружения, что делает программу переносимой внутри своего каталога.
+
[,console]
----
$ g++ main.o -L./lib -lfoo -Wl,-rpath,'$ORIGIN/lib' -o app     <1>
$ readelf -d app | grep -i path                                <2>
----
<1> `$ORIGIN` это специальная подстановка: каталог, где лежит сам исполняемый файл. Кавычки обязательны, иначе шелл попытается развернуть переменную.
<2> Проверить, что путь действительно зашит.

NOTE: Различайте `-L` и `-rpath`. `-L` говорит *линковщику*, где искать библиотеку во время сборки. `-rpath` говорит *загрузчику*, где искать её во время запуска. Забыть второе очень легко: собралось, а запускаться отказывается.
