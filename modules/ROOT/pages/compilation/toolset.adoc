== GCC toolset

=== `gcc` против `g++`

Оба это *драйверы*, а не компиляторы. Разница между ними меньше, чем кажется, и сводится к двум вещям:

. `gcc` определяет язык по расширению файла: `.c` собирает как C, `.cpp` как C++. `g++` собирает как C++ *всегда*, независимо от расширения.
. При линковке `g++` автоматически добавляет `-lstdc++` (стандартную библиотеку C++), а `gcc` нет.

Отсюда классическая ошибка: собрали C++ файл через `gcc`, компиляция прошла, а на линковке посыпались `undefined reference to 'std::cout'` и `operator new`. Лечится либо `g++`, либо явным `gcc main.cpp -lstdc++`.

Практически: для C++ всегда `g++`. Явно задать язык можно флагом `-x`:

[,console]
----
$ gcc -x c++ weird_name.txt -lstdc++ -o app
----

=== Флаги путей и определений

`-I<dir>`::
Добавить каталог в поиск заголовков для `#include`. Заглавная i.
+
[,console]
----
$ g++ -Iinclude -I../common/include main.cpp
----

`-L<dir>`::
Добавить каталог в поиск библиотек на этапе линковки.

`-l<name>`::
Прилинковать библиотеку. Строчная L. Имя пишется без `lib` и без расширения: `-lm` это `libm.so`, `-lpthread` это `libpthread.so`.
+
[,console]
----
$ g++ main.cpp -L./lib -lmytools -lm -lpthread -o app
----

`-D<name>` и `-D<name>=<value>`::
Определить макрос, как будто в начале файла стоит `#define`.

`-U<name>`::
Наоборот, отменить определение макроса.

CAUTION: `-I` (заглавная i) и `-l` (строчная L) в большинстве шрифтов терминала выглядят почти одинаково. Это регулярный источник получаса отладки на ровном месте. Заглавная `-I` про заголовки, строчная `-l` про библиотеки, заглавная `-L` про каталоги с библиотеками.

=== Стандарт языка и версии стандартной библиотеки

[,console]
----
$ g++ -std=c++17 main.cpp        <1>
$ g++ -std=c++20 main.cpp
$ g++ -std=gnu++17 main.cpp      <2>
----
<1> Строгий стандарт.
<2> Стандарт плюс расширения GNU. Это значение по умолчанию у gcc, если `-std` не указан.

Узнать, какой стандарт применяется на самом деле, можно через макрос `+__cplusplus+`:

[,cpp]
----
#include <iostream>
int main() { std::cout << __cplusplus << "\n"; }
----

Значения: `199711` для C++98, `201103` для C++11, `201402` для C++14, `201703` для C++17, `202002` для C++20.

Отдельная тема - *реализация* стандартной библиотеки. Их несколько:

`libstdc++`::
Реализация от GNU, идёт с gcc. Стандарт по умолчанию в Linux.

`libc++`::
Реализация от LLVM, идёт с clang. По умолчанию на macOS. Подключается флагом `-stdlib=libc++`.

`libc` (glibc, musl)::
Это уже библиотека *C*, другой уровень. Её тоже бывает несколько: glibc в обычных дистрибутивах, musl в Alpine. Отсюда, кстати, знаменитая проблема, что бинарь, собранный на Ubuntu, не запускается в Alpine-контейнере.

WARNING: С gcc 5 у libstdc++ поменялся ABI у `std::string` и `std::list`. Совместимость держится макросом `+_GLIBCXX_USE_CXX11_ABI+`. Если линкуете свой код с чужой библиотекой, собранной другим компилятором, и получаете `undefined reference` на функцию, которая явно существует и в имени которой мелькает `__cxx11`, это оно. Лечится пересборкой обеих сторон одинаково или явным `-D_GLIBCXX_USE_CXX11_ABI=0`.

=== Предупреждения

[,console]
----
$ g++ -Wall -Wextra -Werror main.cpp
----

`-Wall`::
Включить основной набор предупреждений. Название врёт: это далеко не все предупреждения, а разумный минимум.

`-Wextra`::
Ещё пачка полезных проверок, которые не вошли в `-Wall`.

`-Werror`::
Считать любое предупреждение ошибкой. Сборка падает.

`-Wpedantic`::
Ругаться на всё, что не по стандарту, в том числе на расширения GNU.

Выключить одно конкретное предупреждение можно через `-Wno-`:

[,console]
----
$ g++ -Wall -Wextra -Wno-unused-parameter main.cpp
----

=== Оптимизация и отладка

`-O0`::
Без оптимизаций, значение по умолчанию. Быстрая сборка, медленный код, зато отладчик показывает ровно то, что написано в исходнике.

`-O1`, `-O2`::
Базовая и стандартная оптимизация. `-O2` это то, что берут для релиза почти всегда.

`-O3`::
Агрессивная оптимизация, активная векторизация и разворачивание циклов. Код может стать больше и, вопреки ожиданиям, иногда медленнее из-за давления на кэш инструкций.

`-Os`::
Оптимизировать по размеру. Для встраиваемых систем.

`-Og`::
Оптимизировать, не мешая отладке. Хороший выбор для отладочной сборки: заметно быстрее `-O0` и при этом отладчик остаётся вменяемым.

`-g`::
Положить в бинарь отладочную информацию (формат DWARF). Не мешает оптимизациям и ортогонален `-O`: комбинация `-O2 -g` совершенно нормальна и нужна, чтобы разбирать падения релизных сборок.

[,console]
----
$ g++ -O0 -g main.cpp -o app_debug
$ g++ -O2 -DNDEBUG main.cpp -o app_release
----

TIP: Если программа работает на `-O0` и ломается на `-O2`, в подавляющем большинстве случаев виноват не оптимизатор, а неопределённое поведение в вашем коде: выход за границы массива, чтение неинициализированной переменной, разыменование нулевого указателя. Оптимизатор имеет право считать, что UB не бывает, и делает выводы, которые в такой программе перестают быть верными. Ищите санитайзерами: `-fsanitize=address,undefined`.
