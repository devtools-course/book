== Шаг 1. Препроцессинг

Препроцессор - это тупая машинка для работы с текстом. Он не знает про типы, функции и классы, он вообще не знает C++. Он умеет только подставлять текст, вырезать текст и склеивать текст. Всё, что кажется в нём умным, на самом деле подстановка.

Запустить его отдельно можно двумя способами:

[,console]
----
$ g++ -E main.cpp -o main.ii     <1>
$ cpp main.cpp                   <2>
----
1) Через драйвер компилятора, правильный способ.

2) Напрямую утилитой `cpp`. Осторожно: `cpp` это *препроцессор C*, а не «C plus plus». Название совпало с расширением файлов C++ по чистой случайности, и это регулярно всех путает.

Посмотреть, во что превратился крошечный файл, очень отрезвляюще:

[,console]
----
$ cat hello.cpp
#include <iostream>
int main() { std::cout << "hi\n"; }

$ g++ -E hello.cpp | wc -l
51234
----

Пятьдесят тысяч строк из двух. Это и есть та самая единица трансляции, которую дальше будет разбирать компилятор.

=== `#include`

Директива `#include` делает ровно одну вещь: берёт содержимое указанного файла и вставляет его *вместо себя*. Буквально, все.

Есть две формы:

[,cpp]
----
#include <iostream>     // угловые скобки
#include "myheader.h"   // кавычки
----

Разница только в порядке поиска файла:

* `<...>` - искать в системных каталогах: то, что задано `-I`, потом стандартные пути (`/usr/include`, `/usr/local/include` и так далее).
* `"..."` - сначала искать в каталоге текущего файла, потом всё то же самое, что и для угловых скобок.

Правило простое: свои заголовки в кавычках, чужие и системные в угловых скобках.

Посмотреть, где именно компилятор ищет заголовки:

[,console]
----
$ g++ -E -v -x c++ /dev/null
...
#include "..." search starts here:
#include <...> search starts here:
 /usr/include/c++/13
 /usr/include/x86_64-linux-gnu/c++/13
 /usr/local/include
 /usr/include
End of search list.
----

А посмотреть, какие файлы реально были включены в конкретную сборку:

[,console]
----
$ g++ -H -c main.cpp 2>&1 | head
. /usr/include/c++/13/iostream
.. /usr/include/x86_64-linux-gnu/c++/13/bits/c++config.h
... /usr/include/features.h
----

Количество точек это глубина вложенности. Очень помогает, когда непонятно, откуда в сборку приехал неожиданный заголовок.
