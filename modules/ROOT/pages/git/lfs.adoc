= Git LFS
:page-authors: Виктория Попова
:description: Git. LFS

Заливать бинарники в Git - дурной тон, и вот почему.

Git хранит *каждую версию каждого файла*. Для текста это дешево: файлы хорошо жмутся, а при упаковке репозитория Git считает дельты - хранит не сами версии, а разницу между ними. С бинарником (архив, картинка, `.psd`, видео, собранный `.exe`) оба механизма не работают: он уже сжат, а изменение одного пикселя меняет весь файл целиком, и дельта получается размером с сам файл.

Итог: закоммитили файл на 100 МБ, поменяли его 10 раз - в репозитории лежит гигабайт. И этот гигабайт тянет к себе *каждый*, кто делает `git clone`, потому что клонируется вся история, а не только последнее состояние. Удалить файл из последнего коммита не поможет - он останется в истории навсегда.

Вдобавок такие файлы невозможно нормально смотреть в `git diff` и невозможно смержить: при конфликте придется выбирать «мой или чужой» целиком.

Git LFS решает это: вместо самого файла Git хранит маленькую текстовую метку-указатель, а сам файл лежит на отдельном LFS-сервере и скачивается по запросу - только та версия, которая вам нужна прямо сейчас.

== Установка

Git LFS - это *не часть Git*, а отдельная программа (расширение), которую надо доставить руками:

[,console]
----
$ sudo dnf install git-lfs        <1>
$ sudo apt install git-lfs        <2>
$ brew install git-lfs            <3>
----
<1> Fedora / RHEL.
<2> Debian / Ubuntu.
<3> macOS.

После установки LFS надо включить - команда прописывает в конфиг Git фильтры (`clean`/`smudge`) и хуки, через которые LFS и подменяет файлы на указатели:

[,console]
----
$ git lfs install                 <1>
Updated Git hooks.
Git LFS initialized.

$ git lfs install --skip-repo     <2>
$ git lfs uninstall               <3>
----
<1> Включить LFS в текущем репозитории (и в глобальном конфиге пользователя).
<2> Только глобальные настройки, без хуков в текущем репозитории.
<3> Обратная операция: выключить LFS, убрать хуки и фильтры.

== Настройка в конкретном репозитории

[,console]
----
$ git lfs track "*.psd"           <1>
$ git lfs track "*.mp4"
$ git add .gitattributes          <2>
$ git add file.psd
$ git commit -m "Add design file"
----
<1> Все `.psd` теперь идут через LFS.
<2> LFS запишет свои настройки сюда, надо закоммитить.

CAUTION: `track` действует только на новые коммиты. Файлы, которые уже лежат в истории, в LFS сами не переедут - для этого придется переписывать историю (`git lfs migrate import`).

Что уже под LFS:

[,console]
----
$ git lfs ls-files
a1b2c3d4e5 * assets/logo.psd
f6a7b8c9d0 * assets/intro.mp4
0123456789 - assets/old-banner.psd      <1>
----
<1> Первая колонка - хэш объекта в LFS, вторая - состояние: `*` файл скачан в рабочую директорию, `-` лежит только указатель.
