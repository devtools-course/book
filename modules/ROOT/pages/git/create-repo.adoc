= Create a repo
:page-authors: Виктория Попова
:description: Git. Создание репозитория

Правильный порядок действий, если вы начинаете новый проект.

== Шаг 1. Создать папку и инициализировать репозиторий

[,console]
----
$ mkdir my-project
$ cd my-project
$ git init
Initialized empty Git repository in /home/user/my-project/.git/
----

По умолчанию `git init` создает ветку `master`. Имя можно задать сразу при создании репозитория:

[,console]
----
$ git init --initial-branch=main        <1>
$ git init -b main                      <2>
----
<1> Первая ветка будет называться `main`, а не `master`.
<2> Короткая форма того же флага.

Чтобы не писать это каждый раз, имя ветки по умолчанию задается один раз в конфиге:

[,console]
----
$ git config --global init.defaultBranch main
----

Подробнее про конфиг - в xref:git/config.adoc[].

== Шаг 2. Сразу добавить `.gitignore`

Это важно сделать *до первого коммита*, иначе рискуете залить в историю всякий мусор: собранные бинарники, кэши IDE, локальные конфиги с паролями. Готовые шаблоны на все языки лежат здесь: https://github.com/github/gitignore.

== Шаг 3. Добавить README.md

`README.md` - файл с описанием проекта в корне репозитория. Это первое, что видит любой, кто открывает ваш репозиторий: и GitHub, и GitLab показывают его содержимое прямо на главной странице проекта.

Минимум, который стоит написать:

* что это за проект и какую задачу решает;
* как его собрать и запустить;
* как с ним работать - примеры команд или скриншот;
* кому писать, если что-то сломалось.

== Шаг 4. Первый коммит

[,console]
----
$ git add .                        <1>
$ git status                       <2>
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   .gitignore
        new file:   README.md

$ git commit -m "Initial commit"   <3>
----
<1> Добавить в индекс все, что есть в рабочей директории (кроме игнорируемого).
<2> Перед коммитом посмотреть, что именно уедет в историю: не попал ли туда мусор, который вы забыли внести в `.gitignore`.
<3> Зафиксировать первый коммит.

== Шаг 5. Создать пустой репозиторий на GitHub

На сайте: *New repository*, задайте имя, *не* ставьте галочки «Add README», «Add .gitignore», «Add license». Иначе на сервере создадутся коммиты, которых нет у вас локально, и первый `push` не пройдет без дополнительных манипуляций.

== Шаг 6. Привязать remote и запушить

GitHub на странице пустого репозитория покажет готовые команды, они выглядят так:

[,console]
----
$ git remote add origin git@github.com:username/my-project.git
$ git branch -M main                <1>
$ git push -u origin main           <2>
----
<1> Переименовать текущую ветку в `main` (на случай, если она называется `master`).
<2> Флаг `-u` (`--set-upstream`) запоминает связь `main → origin/main`, чтобы дальше можно было писать просто `git push` и `git pull` без указания ветки.
